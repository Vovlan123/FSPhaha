# ФСП Талант — краткое описание подхода

## Задача в двух абзацах

ФСП Талант — платформа подбора ИТ-специалистов с обратной механикой: инициатива на стороне работодателя. Кандидат не пишет резюме для витрины. Он проходит обязательный путь: опрос → самооценка грейда → адаптивный тест. По результату он попадает в категорию «специализация × грейд». Работодатель описывает потребность, получает ранжированную подборку с объяснением и сам отправляет конкретному кандидату приглашение. Зарплатная вилка в приглашении обязательна.

Профиль кандидата подтверждается двумя независимыми источниками: результатом теста и достижениями из реестра ФСП (подтягиваются после привязки ФСП ID). Если истории ФСП нет, система это корректно обрабатывает: профиль не штрафуется, работодатель видит понятную плашку.

## Механика тестирования: почему её нельзя «слить»

| Проблема | Решение |
|---|---|
| Единый набор заданий быстро расходится по рынку | **Параметрические шаблоны.** Каждый шаблон — генератор: числа, имена, порядок строк кода и порядок вариантов меняются. Слитый ответ к другому экземпляру не подходит. |
| Генерация нейросетью «на лету» даёт несравнимую сложность | Сложность закреплена **за шаблоном** (параметры IRT a и b), а не за экземпляром. Нейросеть используется только офлайн: создаёт новые шаблоны, которые до включения в банк проходят калибровку. |
| Процент верных ответов несравним при разных наборах заданий | **IRT 2PL.** Кандидат получает оценку уровня θ на общей шкале. Грейд определяется по порогам на этой шкале. |
| Длинный одинаковый тест легко запомнить | **Адаптивный тест (CAT)** на 10–20 вопросов: следующий вопрос подбирается под текущую оценку. Случайный выбор из 4 лучших кандидатов-вопросов и контроль частоты показов разводят маршруты разных кандидатов. |
| Утечка всё равно случается | **Детектор утечек.** Если по шаблону отвечают заметно лучше, чем предсказывает модель (средний остаток > 0,2 и z > 3), шаблон уходит в карантин. |
| Повторными попытками можно перебрать вопросы | Повтор того же грейда — не раньше чем через 30 дней. Шаблоны, которые кандидат видел за последние 180 дней, исключаются. Смена грейда — не чаще раза в 90 дней. |

Грейд никогда не понижается принудительно:

- если заявленный грейд не подтверждён, кандидат может сразу пройти тест на грейд ниже;
- если результат уверенно выше следующего порога, предлагается принять грейд выше без отдельного теста.

## Механика подбора и выхода на контакт

1. **Потребность → структура.** Работодатель вставляет текст. NLP-разбор (словарь навыков с синонимами и правила) заполняет специализацию, грейд, обязательный и желательный стек, формат и вилку.
2. **Рекомендованные категории.** Основная категория, соседние по грейду и смежные специализации, в которых найдены кандидаты с нужным стеком.
3. **Ранжирование.** Балл соответствия складывается из четырёх частей:
   - стек — 40%: навык, подтверждённый тестом, весит больше заявленного, а опровергнутый тестом — меньше;
   - соответствие грейда (категории) — 25%;
   - сила подтверждённого профиля — 20%: тест, ФСП, активность;
   - условия — 15%: зарплата, формат, город.
4. **Объяснимость.** У каждого кандидата список причин со знаками «плюс» и «минус», например: «3 из 4 обязательных навыков, 2 подтверждены тестом», «Призёр всероссийских соревнований ФСП, 2025», «Ожидания выше вилки на 8%».
5. **Уточнение без потери.** Подборка сохраняется. Фильтры применяются к ней, шорт-лист переживает пересчёт, новые кандидаты помечаются.
6. **Приглашение-оффер.** Обязательны вилка «от–до» в рублях, компания, описание и способ связи. Карточка кандидата анонимна, контакты раскрываются только после принятия приглашения. Защита от спама:
   - недельная квота — 20 приглашений;
   - одно активное приглашение на одного кандидата;
   - предупреждение, если вилка ниже ожиданий кандидата.
7. **Обратная связь.** При отказе кандидат указывает причину, при причине «зарплата» — ожидаемую сумму. Работодатель видит это сразу.
8. **Дополнительные каналы:**
   - самостоятельный отклик на вакансию, при котором контакты раскрываются этой компании;
   - регулярные короткие задания от работодателей. Задания освежают профиль и дают работодателю повод для приглашения.

## Интеграция с ФСП

Mock-реестр повторяет OIDC-эндпоинты Keycloak (`/realms/fsp/protocol/openid-connect/*`) и отдаёт API достижений. Чтобы перейти на реальный ФСП ID, достаточно сменить адрес и ключи клиента. Из реестра берём:

- соревнование или мероприятие;
- дисциплину;
- уровень;
- результат и место;
- команду и роль в ней;
- дату.

Из этих данных считаются балл ФСП (с затуханием по давности) и бейджи для работодателя.

## Как проверяем качество (валидация)

- **Тест.** Синтетические кандидаты с известным истинным уровнем проходят настоящий движок тестирования. Считаем:
  - точность присвоения грейда;
  - стабильность при повторном прохождении;
  - дискриминативность шаблонов;
  - насколько завышается грейд у «списывающих»: фиксированный тест против нашего;
  - время обнаружения утечки детектором;
  - восстановление параметров шаблонов по смоделированным ответам.
- **Подбор.** Пары «потребность — кандидат» с эталонной разметкой релевантности. Считаем Precision@10 и nDCG@10 и сравниваем с бейзлайном «совпадение ключевых слов в резюме».

Скрипт: `backend/validation/run_validation.py`, отчёт: `docs/validation/report.md`.
